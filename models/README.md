# Локальные модели (Ollama + MLX на Apple Silicon)

Ollama ≥ 0.31 на Apple Silicon работает на движке **MLX** (Metal, unified memory) —
это заметно быстрее и экономнее по памяти. Поэтому берём MLX-теги.

## Ограничение железа

- **MacBook/Mac этой сборки: Apple M5, 16 ГБ unified RAM.**
- 16 ГБ — мало. Реальный потолок — модели **до ~9 ГБ** в 4-bit/MLX. Модели работают
  **по очереди**, не одновременно (обе сразу в 16 ГБ не поместятся с контекстом).

## Установленные модели

| Роль | Тег | Размер | Заметки |
|------|-----|--------|---------|
| Чат / общее | `gemma4:12b-mlx` | 7.7 ГБ | Контекст 256K, text+image, MTP-ускорение на Apple Silicon |
| Код | `qwen3.5:9b-mlx` | 8.9 ГБ | Лучший *реально влезающий* в 16 ГБ MLX-кодер |

```bash
ollama pull gemma4:12b-mlx
ollama pull qwen3.5:9b-mlx
ollama list          # проверить
ollama run qwen3.5:9b-mlx "напиши тест на функцию X"
```

## Честные оговорки (важно)

- **`qwen3-coder` (выделенный кодер) в 16 ГБ НЕ помещается**: минимальный тег — 30B / ~19 ГБ,
  MLX-варианта у него нет. Поэтому кодером взят `qwen3.5:9b-mlx`. При апгрейде RAM (≥32–48 ГБ)
  стоит перейти на `qwen3-coder:30b-a3b-q4_K_M` (~19 ГБ, MoE, 3B активных).
- `gpt-oss:20b` (~13–14 ГБ) технически влезает, но впритык: короткий контекст, риск свопа.
  Держим как опцию для коротких задач, не по умолчанию.

## Подключение локальных моделей к агентам

Ollama даёт OpenAI-совместимый эндпоинт на `http://localhost:11434/v1`.
Его можно указать провайдером в OpenCode (`/connect` → custom/OpenAI-compatible),
а также в любом инструменте, поддерживающем OpenAI-совместимый base URL.
